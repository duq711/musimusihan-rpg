# 정적 원본 GLB의 영상 비교용 3D 기준점

작성: 2026-09-10. 원본 GLB의 POSITION 정점, 삼각형 인덱스, 누적 노드 변환만 읽어 확인했다. Blender 실행·렌더·모션 생성·원본 수정은 하지 않았다. 전체 수치와 정점 근거는 `GUIDE_LANDMARKS.json`, 재현 파서는 `inspect_guide_landmarks.py`에 있다.

**영상의 G(날축과 가드의 교차점), 코드 HandGrip, 손목은 서로 다른 점이다.** 이 원본에서 G와 HandGrip은 약 99.02mm, G와 손목은 131.05mm 떨어져 있다. `GRIP_CENTER`라는 코드 이름을 영상 G로 해석하지 않는다.

## 좌표·원본

- 파일: `godot-game/assets/3d/player/sword_hold_long_grip/SwordHold_Static.glb`
- SHA256: `2b94cc385f837fe253552cd654cb1f665246f61cdee5227814d63049da9f22fb`
- 원본: 메시 11개, skin 0개, animation 0개. GLB에는 가드 중심이나 손목 관절을 지정한 별도 bone/marker가 없다.
- 단위: 미터. 카메라 로컬 +X 오른쪽, +Y 위, -Z 전방.
- `source_camera = cumulative_original_node_transform * raw_vertex`.
- `canonical = inverse(SOURCE_READY) * source_camera`. 새 클립 t에서 비교할 점은 `T(t) * canonical`이다. 아래 source_camera 값을 새 클립의 고정 위치로 사용하지 않는다.
- POSITION은 float32다. JSON의 긴 소수는 산술 결과이며 원본의 정밀도가 그 자릿수까지 정확하다는 뜻이 아니다.

## Windows에 사용할 기준점

표 값은 읽기 쉽게 반올림했다. G·B·P 등은 정점 단면의 중심으로 정의한 가상 기준점이며, 단일 표면 정점과 반드시 일치하지 않는다.

| 표식 | 의미 | canonical `[x,y,z]` | source_camera `[x,y,z]` |
| --- | --- | --- | --- |
| **G** | 날축에서 가드 뿌리 단면의 중심 | `[0,-0.009,0]` | `[0.323710,-0.012450,-0.590149]` |
| **B** | 실제 칼끝 단면 중심 | `[0,1.035,0]` | `[0.468286,1.016259,-0.486267]` |
| **H** | 코드 `HandGrip` 파지 기준 | `[0,-0.108,0.002]` | `[0.308548,-0.109934,-0.598627]` |
| **W** | 코드 `REST_WRIST` 소매 손목 기준 | `[0.0679751875,-0.1080001335,0.0524637313]` | `[0.317683,-0.119661,-0.515025]` |
| **GL** | 가드 -X 끝 단면 중심 | `[-0.152,0.016,0]` | `[0.224807,0.037623,-0.697107]` |
| **GR** | 가드 +X 끝 단면 중심 | `[0.152,0.016,0]` | `[0.429537,-0.013255,-0.478217]` |
| **P** | pommel 몸체 최대 폭 단면 중심 | `[0,-0.34420009,0]` | `[0.277291,-0.342740,-0.623503]` |
| **P_end** | 자루 최하단 peen 끝 단면 중심 | `[0,-0.36760007,0]` | `[0.274050,-0.365798,-0.625831]` |

P는 재현 가능한 단면 중심이다. pommel의 무게중심이나 모델링 당시 원점은 GLB 정점만으로 확정하지 않는다. 별도로 계산한 pommel 몸체 AABB 중심은 canonical `[0,-0.34127507,0]`이며 P와 약 2.925mm 다르다.

## 코드 marker와 실제 정점 대조

**BladeTip은 맞는다.** `Sword_PittedBlade`의 최대 canonical y는 1.03499997m다. 끝단은 폭·두께 약 0.2mm의 작은 단면이고, 그 중심과 코드 `(0,1.035,0)` 사이 차이는 약 `7.73e-8m`로 원본 float32·변환 오차 수준이다. POSITION accessor 63/69의 끝단 정점이 근거이며 정확한 vertex index 범위는 JSON에 있다. 단일 정점 하나를 임의로 칼끝 중심이라고 선택하지 않았다.

**HandGrip은 가드나 긴 자루 전체의 중심이 아니다.** `Sword_GripLeather` 삼각형을 canonical `y=-0.108` 평면과 교차시켜 얻은 단면 범위는 x 약 `[-0.02130142,+0.02130139]`, z 약 `[-0.01433584,+0.01433596]`다. 코드 H는 그 범위 안쪽의 파지 기준이며 blade 중심 평면에서 +Z로 2mm 떨어져 있다. 근거는 POSITION accessor 52, 교차 삼각형의 정점 650–779이다. 표면 꼭짓점·소재 경계·긴 자루 전체의 중점과 일치한다는 주장은 하지 않는다.

**W는 코드에서 정한 손목 연결점이다.** 원본에는 bone이 없으므로 이번 GLB 측정만으로 독립적으로 저장된 해부학적 관절이라고 확인할 수 없다. 현재 팔 연결 계약에서 사용하는 W를 그대로 기록했다. H–W 거리 약 84.66mm를 없애거나 둘을 겹치게 배치하면 파지와 소매 연결이 바뀐다.

## 가드 G와 날축의 근거

`Sword_SwordsmanLongsword_Surface`에는 가드·pommel·금속 연결부가 합쳐져 있다. 삼각형 연결성을 검사하고 primitive 경계의 중복 정점을 1e-6m 기준으로 용접해 읽으면 별도 금속 island 5개가 확인된다. x 폭이 약 0.304m이고 y 범위가 `[-0.0174,+0.02303356]`인 island가 가드다. 이 처리는 분석 메모리에서만 하며 원본을 바꾸지 않는다.

그 가드의 `x≈0` 단면은 y `[-0.0174000065,-0.0005999999]`, z 약 `[-0.0056,+0.0056]`다. 이 단면 중앙을 blade축과 만나는 **G=(0,-0.009,0)**로 정의했다. 근거 정점은 node 10, primitive 0/POSITION accessor 75의 275–290 및 primitive 1/accessor 81의 92–107이다. 32개 record는 UV/normal/material 경계의 중복을 포함한다.

날의 y=-0.01부터 1.035까지 12개 실제 단면 중심은 canonical +Y축과 float32 오차 수준에서 일치한다. 표본 단면의 축 이탈은 JSON에 기록했다. 따라서 비교용 날축은 canonical 원점 `(0,0,0)`, 방향 `(0,1,0)`이다. source_camera 방향은 `normalize(SOURCE_READY.basis.y)`, 약 `(0.13848246,0.98535349,0.09950393)`다. 폭 방향은 canonical X, 날의 앞뒤 두께 방향은 canonical Z다.

가드에 두께가 있어 실제 겹치는 영역 전체를 하나의 유일한 교차 정점으로 볼 수는 없다. 영상의 수동 표시가 상단 테두리, 중심선, 가려진 날의 시작 중 어느 것을 뜻하는지 확인해야 한다. 이 문서 G는 **뿌리 단면의 중앙**이라는 일관된 비교 규약이다. 기하학적 근거는 높지만 원본 영상의 한 픽셀과 정확히 대응한다는 확정은 아니다.

가드는 양끝이 위로 휘어져 있다. GL/GR의 중점은 약 `(0,+0.016,0)`이며 G보다 25mm 위다. **양끝을 직선으로 연결한 중점, 전체 가드 AABB 중심, 코드 피벗 원점 `(0,0,0)`을 G 대신 쓰지 않는다.** 피벗 원점도 G와 9mm 다르다.

## 영상 대조 시 적용

1. 프레임 비교 표식은 B/G/H/W를 별도로 표시한다. root에서 표시한 영상 G에는 `crossguard_axis_intersection`을 사용하고 `hand_grip_marker`를 대입하지 않는다.
2. 각 프레임에서 같은 canonical 점을 실제 검 변환 T로 이동한 뒤 검토 카메라로 투영한다. source_camera 좌표를 모션 transform에 다시 곱하지 않는다.
3. G 위치, G→B 날 방향, GL/GR 가드 기울기, W와 팔꿈치 연결을 각각 본다. 카메라 원근과 깊이 차이가 있어 실제 3D 길이 비율을 2D 픽셀 비율로 그대로 강제하지 않는다.
4. 새 idle 깊이를 고정하지 말고 실제 모델 투영과 손목–어깨 도달 거리를 함께 맞춘다. 화면 밖으로 나간 칼끝이나 가려진 손목은 확인 불가능으로 표시하고 가상의 관측값을 만들지 않는다.

이 기준점은 기존 사용자 모델을 정확히 비교하기 위한 것이다. 참조 영상의 3D 모델·카메라·관절 구조까지 복원했다는 의미는 아니다.
