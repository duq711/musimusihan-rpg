# 영상 참고 검 모션 전달·통합 계약

이 문서는 Windows 모션과 Godot 사이의 전달·통합 계약입니다. 실제 영상 분석은 `reference/reference_notes.md`, 최종 제작 지시는 `AUTHORING_BRIEF.md`에 기록합니다. 실제 모션 제작·리깅·베이크·렌더링은 Windows에서 실행하고 Mac에서는 좌표 변환과 게임 재생·검증을 수행합니다. 이 문서 자체는 제작·납품 완료의 증거가 아닙니다.

## 산출물

- `motion_manifest.schema.json`: Windows가 반환할 실제 제작 결과 JSON의 구조.
- `delivery_requirements.json`: 원본 해시, 좌표계, 초기 일곱 동작 클립, 현재 게임의 시간과 검증 조건. 실제 애니메이션 데이터가 아닙니다. 최종 납품에는 아래의 `idle`도 필수입니다.
- 향후 Windows 결과: 별도 `.blend`, `motion_manifest.json`, 참조 구간 기록, 실제 렌더 미리보기, 검증·실행 로그. JSON 안에는 이미지가 아니라 샘플 시각·위치·쿼터니언만 저장합니다.

원본은 `asset-staging/sword_hold_long_grip_integration/source/model/SwordHold_Static.blend`와 `godot-game/assets/3d/player/sword_hold_long_grip/SwordHold_Static.glb`입니다. 원본을 덮어쓰지 않습니다. 새 산출물은 `windows_output/<고유한 반복 이름>/`에 받습니다. 실제 제작 호스트, Blender 실행 파일·버전, 출력 경로와 해시를 기록한 뒤 통합합니다.

## 좌표와 원본 정규화

런타임 목표는 **카메라 로컬 좌표에서 정의한 기존 `weapon_pivot`의 절대 변환**입니다. 미터 단위이며 +X 오른쪽, +Y 위, −Z 전방입니다. `position`은 `[x,y,z]`, `rotation_xyzw`는 `[x,y,z,w]` 순서이고 스케일은 항상 1입니다. 쿼터니언은 단위 길이이며 연속 샘플의 내적이 음수이면 다음 샘플의 부호를 반전합니다. 행렬은 열벡터 관례를 사용합니다.

현재 원본 GLB의 메시 정점은 작성된 카메라 구도로 배치되어 있습니다. `scripts/sword_long_grip_visual.gd`는 `S = SOURCE_READY`를 사용해 `v_canonical = inverse(S) * v_authored_camera`로 한 번 정규화합니다. 손과 검의 상대 위치는 고정입니다. 새 모션이 이 런타임 메시를 움직이려면 `T_weapon(t) = D_camera(t) * S`를 내보내야 합니다. 정점이나 `S`를 두 번 변환하면 손·검 위치가 잘못됩니다.

**권장 Blender 경로:** 원본을 보존한 별도 씬에서 검과 손의 강체 구도를 움직이는 `MotionRoot` 컨트롤을 만듭니다. 기준 카메라를 고정하고 다음 값을 평가합니다.

```text
A(t)    = inverse(Camera.matrix_world) * MotionRoot.matrix_world(t)
A_rest  = inverse(Camera.matrix_world) * MotionRoot.matrix_world(rest)
D(t)    = A(t) * inverse(A_rest)
T_sword = D(t) * SOURCE_READY
```

Blender 카메라 **로컬 축**은 Godot 카메라와 마찬가지로 +X 오른쪽, +Y 위, −Z 시선 방향입니다. 따라서 위의 `D(t)`는 추가 축 회전 없이 카메라 공간 운동으로 사용할 수 있습니다. `MotionRoot`의 원래 로컬 축은 `A_rest`의 역변환에서 소거됩니다. 카메라의 물리적 구도와 손·검 원본 배치가 일치하는지는 첫 프레임 겹치기 검증으로 확인합니다. 카메라의 모션은 베이크하지 않습니다.

Blender **월드 좌표**를 직접 옮길 때의 기저 변환은 `C(x,y,z)=(x,z,-y)`입니다. 일반 오브젝트의 로컬 좌표까지 같은 관례로 바꿀 때 `T_G = C * T_B * inverse(C)`를 사용합니다. 이 공식과 앞의 카메라 로컬 델타 공식을 혼합하지 않습니다. 특히 카메라 로컬 샘플에 `C`를 다시 곱하거나 쿼터니언 성분을 임의로 재배열하지 않습니다. 쿼터니언은 최종 `T_sword`의 회전 행렬에서 추출합니다.

`SOURCE_READY`의 기저는 `delivery_requirements.json`의 `basis_columns`에 저장합니다. 각 배열은 X·Y·Z 기저 **열**입니다. `position`은 마지막 열입니다. GLB를 통째로 카메라 아래에 놓는 경로는 이 정규화된 `weapon_pivot` 경로와 다르므로 서로 교체해서 사용하지 않습니다.

방패 트랙도 카메라 로컬 절대 변환이지만 기준 프레임은 `shield_pivot`입니다. `T_shield(t)=D_shield(t)*S_shield`로 제작하고 `S_shield`는 현재 `CHOREOGRAPHY.shield(0,0,"ready",0,0,variant)`를 그대로 사용합니다. 모든 좌표값은 `shield_model` 자식 변환이 아닌 **부모 피벗** 기준입니다. 방패 미장착 시 트랙을 평가해도 표시하거나 장비를 지급하지 않습니다.

원본 정규화 진단에서 `T_sword=S`, `D=identity`일 때 원본 장갑과 검의 접촉이 동일해야 합니다. 새 `idle`은 영상 구도에 맞게 이동할 수 있으므로 첫 납품 프레임에 항등 델타를 강제하지 않습니다. `HandGrip=(0,-0.108,0.002)`, `BladeTip=(0,1.035,0)`를 사용해 정규화와 실제 파지를 확인합니다. 축 확인은 +X·+Y·−Z로 각각 10cm 이동시키는 **검증용 씬**에서 하고 이 진단 변환을 납품 클립에 포함하지 않습니다.

## 클립과 시간

필수 클립은 `idle`, `run`, `takeoff`, `air`, `land`, `right_diagonal`, `left_reverse`, `overhead`입니다. `idle`, `run`, `air`는 루프이고, 나머지는 한 번 재생합니다. 모든 클립에 `sword`, `shield` 두 트랙을 같은 시각 범위로 포함합니다. 각 트랙의 첫 샘플은 0초, 마지막은 클립 길이이며 시각은 엄격하게 증가합니다. 정규 샘플 사이에도 공격의 준비 종료·타격·활성 종료 등 중요한 시각을 정확히 삽입합니다.

`idle`은 작은 호흡을 가진 부드러운 루프이며 실제 준비 자세로 사용합니다. 원본 카메라 구도와 달리 손을 화면 오른쪽 아래로 내리는 연출도 `D*S`의 모션 변환으로 표현합니다. `SOURCE_READY`는 원본 메시 정규화 기준으로 계속 고정하며, 새 준비 자세에 맞춰 원본 메시 정규화 값을 변경하지 않습니다. 이동↔준비·공격↔준비 전환은 반환된 `idle` 자세에 맞춰야 합니다.

60Hz 이상(권장 120Hz)으로 베이크하고 Godot에서는 시간으로 인접 샘플을 찾습니다. 런타임은 실제 이웃 샘플 간격을 사용하는 위치·쿼터니언 3차 보간으로 접선 속도를 연결합니다. 샘플의 원래 시각에는 그 자세를 정확히 반환하며, 루프 끝의 이웃도 주기를 넘어 연결합니다. 초기 선형/SLERP 선언이 있는 원본 납품은 보존하고, 통합 기록에는 실제 런타임 보간을 구분해 적습니다. 이 보간 방식도 실제 30/60/120Hz 평가로 끊김을 검사합니다. 루프는 양 끝 변환과 접선 속도가 이어져야 합니다. 영상에서 관찰한 일시적인 화면 이탈은 허용하지만 급격한 손목 회전과 팔 길이 과신장은 별도로 검사합니다.

공격의 `timing`은 `windup_seconds`, `active_seconds`, `hit_seconds`, `recovery_seconds`를 가집니다. `hit_seconds`는 **활성 구간 시작으로부터의 상대 시각**입니다. 전체 클립 길이는 준비+활성+회수이며, 전체 타격 시각은 준비+타격입니다. `timing`은 제작 데이터의 의미이며 피해나 비용을 직접 발생시키지 않습니다.

현재 검방패 기준은 준비 0.22초, 활성 0.30초, 타격 0.145초, 약공격 회수 0.47초입니다. 검 단독 기준은 준비 0.22초, 활성 0.16초, 타격 0.055초, 약공격 회수 0.47초입니다. 강공격 회수는 두 경우 모두 0.68초입니다. 이 값은 현재 코드의 기준이며 영상 분석 없이 새 모션 시간으로 확정하지 않습니다.

기존 전투 시간을 유지할 때는 `phase_resample` 방식으로 샘플링합니다. 준비는 실제 0.22초까지 제작 준비 구간을 재생한 뒤 손을 멈추고 차지를 유지합니다. 실제 `ACTIVE` 진입 시 제작 활성 시작으로 이동합니다. 활성은 `[0, 실제 타격, 실제 활성 종료]`를 `[0, 제작 타격, 제작 활성 종료]`에 단조 PCHIP 곡선으로 대응시켜 접촉 시각과 속도를 함께 연결합니다. 회수는 실제 `lerpf(0.47,0.68,charge)`를 제작 회수 길이에 대응합니다. 게임 재생은 영상의 원래 구간 길이와 다르므로 미리보기와 결과 기록에 명시합니다.

새 모션의 영상 유사성을 평가하려면 참조 영상 구간별 달리기 자세·보폭 주기·손의 상하좌우 폭, 이륙 대비/공중 유지/착지 반동, 베기 준비/가속/접촉/잔여 궤적/회수의 차이를 먼저 기록합니다. 아직 분석하지 않은 수치를 추정해 제작 완료로 표시하지 않습니다.

## 실제 플레이 상태 연결

`scripts/player.gd`가 상태를 결정하고 애니메이션 모듈은 상태를 표현합니다. 샘플 재생으로 `velocity`, 기력, 피해, 장비 또는 카메라 조준을 바꾸지 않습니다.

1. **달리기:** 실제 지상 이동과 달리기 속도·자격을 사용합니다. Shift 입력만으로 재생하지 않습니다. 전투·가드로 이동 속도가 줄면 달리기 모션 가중치도 내려갑니다. 보행↔달리기는 속도에 맞춰 연속 전환하고 갑작스러운 입력 방향 변경으로 루프 시간을 되감지 않습니다.
2. **이륙:** 실제 점프 승인(바닥, 기력, 준비 상태 등) 순간만 시작합니다. 점프 기력 12는 기존 `_update_movement()`가 한 번 소비합니다. 낮은 천장으로 점프가 짧아져도 고정 시간 전체를 강제로 재생하지 않습니다.
3. **공중:** `move_and_slide()` 이후 바닥 판정을 사용합니다. 낙하로 절벽에서 떨어진 경우 이륙 동작을 억지로 발생시키지 않고 공중 자세로 전환합니다. 공중에서는 지상 보폭 흔들림을 억제합니다.
4. **착지:** 이전 프레임 공중→현재 바닥의 실제 전환에서 한 번 시작합니다. 충돌 전 수직 속도를 보존해 반동 강도를 정하되 작거나 반복되는 바닥 판별 변화가 계속 착지를 재시작하지 않게 합니다. 착지 중 재점프하면 현재 자세에서 이륙으로 이어집니다.
5. **공격:** 기존 `begin_sword_attack`→준비→실제 활성→실제 회수 시계에 연결합니다. 공격 중에는 공격 트랙이 검 자세를 소유하고 이동·공중 자세는 낮은 가중치의 잔여 효과로만 합성합니다. 점프 중 공격이 허용되는 현재 조건도 유지·검증합니다.
6. **가드·충돌:** 현재 방패 올리기/내리기 반전과 피격 반동을 유지합니다. 검격 충돌 시 **합성된 실제 현재 검/방패 자세**를 저장한 뒤 회수해야 하며 제작 활성 끝 프레임으로 건너뛰지 않습니다.
7. **중단·복귀:** F2·인벤토리·상자·안전지대·야영·사망·장비 교체에서 기존 중단 정책을 따라 상태와 전환 출발 자세를 정리합니다. 메뉴 일시정지 중 모든 새 시계가 정지해야 합니다. 장비를 다시 꺼낼 때 이전 공중/착지/공격이 남지 않아야 합니다.

기본 구현은 원본 장갑과 검의 고정 파지를 유지하고 소매 3개의 기존 연결 함수를 재사용합니다. 새 클립을 적용하면서 기존 `MOTION.locomotion`의 검 흔들림이 중복되지 않도록 검 전용 합성 경로를 분리합니다. 활·철퇴·지팡이에는 새 클립을 적용하지 않습니다. 임의의 새 Skeleton3D를 현재 정적 모델이라고 표시하지 않습니다.

## 게임 통합 범위

- `scripts/first_person_motion.gd` 또는 별도 `reference_sword_motion.gd`: 데이터 로드, 샘플 보간, 전투 구간 대응. 누락·잘못된 입력을 명확히 검출하며 시간/위치의 비유한값과 단위 길이가 아닌 쿼터니언을 거부합니다.
- `scripts/player.gd`: 실제 운동 전환, 검 전용 합성, 중단/초기화/일시정지, 검격 충돌 시 합성 자세 보존, snapshot에 관찰용 모션 상태 추가.
- 원본 정적 검 모델은 기존 경로와 해시를 유지합니다. 새로운 모션 파일은 별도 경로에 추가하고 제작 원본과 provenance를 보존합니다.
- `scripts/test_room_catalog.gd` + `scripts/test_room.gd`: 달리기, 점프/착지, 이동→점프→착지→공격 연속 시험 항목을 추가합니다. 기존 세 베기 항목이 새 클립을 실제 사용하도록 연결합니다. 시험용 평지·낮은 장애물·표적·재시험 준비를 제공합니다.
- `TEST_ROOM.md`와 `README.md`: 실제 조작, 달리기/점프 시험과 검증 명령을 갱신합니다. 영속 상태는 추가하지 않는 편이 좋습니다. 필요하다면 snapshot/restore와 `test_room_session_test.gd`도 같이 확장합니다.

## 자동 검증과 실제 화면 검토

**데이터:** JSON 스키마 검증에 더해 원본 해시, Windows 실행 증거, 필수 클립, 단조 시간, 끝 시각, 단위 쿼터니언, 연속 부호, 스케일 없음, 루프 변환/속도 연결, 모든 공격 경계 샘플, 전체 시간 합계를 확인합니다. 스키마만으로 수치 관계·실행 증거의 진실성은 보증되지 않습니다.

**실제 물리:** 시험 뷰포트에 실제 CharacterBody3D와 충돌 바닥/낮은 천장/단차를 구성합니다. 외부 OS 입력·마우스 캡처를 사용하지 않고 게임의 실제 이동 경로를 호출하거나 프로젝트에 맞는 내부 입력 어댑터를 사용합니다. 가속/감속, 지상 달리기, 달리기 자격 상실, 정상 점프, 점프 거절, 절벽 낙하, 천장 충돌, 착지 한 번, 착지 중 재점프를 확인합니다. 모션 상태 변수만 직접 바꾼 시험을 실제 물리 시험이라고 보고하지 않습니다.

**실제 전투:** 최소/최대 차지의 세 베기, 단독/방패 조합, 현재 기력 비용, 실제 표적 피해, 실제 칼날 검격 충돌, 충돌 시점부터 부드러운 회수, 장비 교체·F2 취소를 검사합니다. 표시된 칼날과 실제 피해 시각의 정합성을 검사합니다. 현재 `_resolve_active_attack()`의 검격 유예가 있는 상황도 포함합니다.

**팔·카메라:** 원본 장갑/검 형상·재질·접촉 유지, 소매 접합, 손목/팔 길이, 정확히 두 팔 표시, 조준 불변, 손의 화면 범위, 근접 클리핑을 확인합니다. 모든 클립을 30/60/120Hz로 평가하고, 일시정지 전후의 실제 피벗과 관절·시계가 같은지 확인합니다. 원본 모델 검증의 정적 파지 가정을 삭제해서 실패를 숨기지 않습니다.

**테스트룸:** 새 ID 등록뿐 아니라 run_feature의 실제 준비, 각 모션의 실사용, 표적/기력 변화, 반복 F2, 초기화, 종료 시 기존 원정/인벤토리 객체/개별 강화 정보 복원을 확인합니다.

기본 회귀 실행은 `godot-game/tests/run_headless_tests.sh sword_long_grip first_person_motion sword_attack_variants sword_shield_choreography sword_clash test_room_session`이며 새로운 운동 시험도 같은 실행기에 자동 발견되도록 `*_test.gd`로 추가합니다. 헤드리스는 이미지 품질을 검증하지 않습니다.

실제 시각 검토는 허용된 `run_embedded_preview.sh` 경로로 창·커서·포커스·오디오 없이 수행합니다. 새 달리기/점프/착지/연속 전투 시퀀스를 `first_person_motion_preview.gd`에 추가하고 새 반복 폴더에 30fps 이상으로 저장합니다. 1인칭 76도 카메라의 연속 화면과 같은 시각의 좌/우/상/하 팔 모습을 확인합니다. 참조 영상과 주기/프레이밍/궤적을 비교하는 자료는 실제 캡처와 생성/참조 이미지를 구분합니다. `*_QA_INTERACTIVE=1`은 자동 실행하지 않습니다.
