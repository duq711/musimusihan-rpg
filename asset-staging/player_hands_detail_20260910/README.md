# 플레이어 양손 — 디테일 모델링

2026-09-10 사용자의 “이제 모델링을 디테일하게 깎아” 요청에 따른, 기존 양손 그레이박스의 후속 제작이다. 같은 양손 작업에 대한 Mac 제작 지시를 이어서 적용한다. 역할은 캐릭터 그래픽이며 게임의 전투·경제·서사 규칙은 이 작업의 대상이 아니다.

## 제작 범위

- 현재 플레이어의 원본 중립 팔을 기준으로 손 표면의 관절·접힘을 다듬는다.
- 손톱은 얇은 곡면 메시로 만들고 각각의 말단 손가락 본에 스킨한다.
- 장갑 가장자리와 봉제선, 브레이서와 소매의 디테일을 기하로 제작한다.
- 색칠·텍스처 베이크 작업에 앞서 형태를 검토하는 중립 회색 재질을 사용한다.
- 원본 손목 위치, 양손 방향, 16개 본과 게임의 접촉 기준을 유지한다.
- 기존 원본과 약 1만 삼각형 그레이박스를 보존하며 새 GLB와 편집 가능한 Blender 파일로 납품한다.

## 실행 환경과 보존

Mac의 `/Applications/Blender.app/Contents/MacOS/Blender`를 별도 백그라운드 프로세스로 실행한다. 기존 Blender 세션이나 화면의 Godot 편집기를 제어하지 않는다. MCP 등록과 실제 연결은 구분하며, 이번 제작은 직접 실행한 Blender로 수행한다.

입력은 `../player_hands_greybox_20260910/input/`의 `left_arm.glb`, `right_arm.glb`, `gravebound_player.glb`다. `baseline/source_hashes.json`은 변경 전 게임 코드의 사본에 대응하며, `baseline/preserved_assets.json`은 기존 원본·그레이박스·납품 파일 40개의 해시를 기록한다.

## 검증 방법

`tools/verify_hands_detailed.py`는 전달할 Blender 파일과 좌우 GLB를 다시 열어 원본 16개 본의 전체 기준 행렬, 손 방향, 가중치, 다섯 손가락의 실제 메시 변형을 검사한다. 손톱은 각 말단 본에 고정된 좌표가 굽힘 중에도 유지되는지 확인한다. 원본 표면과의 거리도 측정해 장식 추가 이외에 손 표면 자체의 변화가 있는지 검증한다.

`tools/render_detail_comparison.py`는 기존 그레이박스와 디테일 GLB를 같은 카메라·배율·조명으로 직접 렌더한다. PNG를 후처리해 모델 차이를 만드는 작업은 하지 않는다.

게임 검증은 `godot-game/tests/run_headless_tests.sh`를 사용한다. 실제 화면은 프로젝트에서 감사된 `tests/run_embedded_preview.sh`의 창 없는 GPU 렌더러로 검토한다. 이 프리뷰는 외부 입력·마우스 캡처·데스크톱 화면 캡처를 사용하지 않는다.

## 최종 산출물과 검토 결과

최종 모델은 **`mac_output/iteration_03/`**이다. 최초 렌더에서 발견한 손가락 사이로 튀는 가장자리와 손톱 면 방향 오류를 수정했다. 장갑의 말림은 실제 피부·장갑 재질 경계의 5개 연결선을 따라 생성하며, 손톱은 손가락 표면에 붙는 얇은 둥근 사각 윤곽이다. 이전 반복본은 제작 기록으로 보존한다.

| 항목 | 최종 결과 |
|---|---|
| 삼각형 | 좌우 각각 57,346개, 한쪽 팔 전체 기준 |
| 구조 | 한쪽당 9개 메시·1개 스킨·16개 본 |
| 손톱 | 한쪽당 5개, 각각 640삼각형, 해당 말단 본에 고정 |
| 손 | 좌 3,657 / 우 3,659개 정점 조각, 마디·접힘과 손등 패널 절개 |
| 장갑 | 손가락 가장자리 5개, 실제 입체 봉제 91땀/손 |
| 팔 | 브레이서 35땀·소매 20땀, 팔꿈치 주변의 실제 소매 주름 |
| 재질 | 피부·장갑·소매·손톱·봉제선의 중립 회색 5종 |
| 좌표 보존 | 원본 손목 오차 0m, 16개 본 기준 행렬의 최대 성분 오차 약 1.49e-7 |

Blender 5.2.1 LTS를 Mac 백그라운드에서 실행했다. 독립적인 Blender 재열기·GLB 재임포트 검증이 통과했으며, 원본 표면과의 거리 측정에서도 손 표면 자체의 변화를 확인했다. 편집 파일은 외부 이미지·링크 라이브러리 의존성이 없다.

최종 Blender 렌더 5장(손등·손바닥·측면·손등 근접·손바닥 근접), `comparison_03/greybox_to_detailed.png`의 같은 카메라·조명 전후 비교, 실제 게임 GPU 렌더 6장을 직접 검토했다. 게임 캡처는 `godot-game/artifacts/visual_qa/player_hands_detailed/final_03/`에 있다. 빈손·활 당김·발사 후 손 펴기·상자 접촉·뚜껑 들어 올리기와 동일 자세의 그레이박스 비교를 포함한다.

## 게임 연결과 자동 검증

`godot-game/assets/3d/player/hands_detailed/`에 독립 검증한 좌우 GLB를 그대로 가져왔다. 테스트룸 → **기본 → 캐릭터 그래픽 · 양손 디테일 모델**에서 실행한다. 왼쪽 상자는 `E`, 활은 `I`에서 장착 후 `LMB`로 당기고 놓는다. `F2`로 기존 **양손 그레이박스** 항목과 비교할 수 있다. 다른 시험·초기화·종료 시 기존 외형을 복구한다.

아래 6개 자동 검증이 통과했다. 실행 로그는 `godot_regressions_01.log`, `godot_hands_final03.log`다.

- `player_hands_detailed`: 실제 기하 차이·피부/봉제/손톱 변형·렌더 레이어·실제 활/상자 동작·모델 상호 배타 전환·원정 상태 복원
- `player_hands_greybox`: 이전 그레이박스의 동작·리소스·시험 복원 유지
- `player_arm`, `weapon_hand_contacts`, `chest_hands`, `test_room_session`: 관련 기존 동작 회귀

창 없는 실제 GPU 프리뷰도 통과했다(`godot_preview_final03.log`). 이 검증은 OS 입력을 직접 조작한 수동 플레이 테스트가 아니라 실제 게임 함수와 관절을 구동한 렌더 검증이다.

## 납품 및 범위

`exports/Player_Hands_Detailed_2026-09-10/`와 같은 이름의 ZIP에 Blender 원본, 게임용 좌우 GLB, 배치된 양손 검토용 GLB, 렌더·게임 캡처, 제작·검증 도구와 보고서를 넣었다. 최종 기계 판독 결과는 `validation_summary.json`이다.

이번 결과는 모델 형태를 다듬은 중립 회색 버전이다. 컬러 텍스처·노멀맵 베이크·애니메이션 클립 제작은 포함하지 않는다. 게임의 기본 외형은 기존 그대로이며, 새 모델은 일반 팔과 활·상자 시험 경로에 선택 적용된다. 별도로 제작된 기본 검·방패 전용 손과 전신 모델은 교체하지 않았다.

기존 원본·그레이박스·납품 에셋 40개를 해시로 재확인해 보존했다. 관련 테스트에서 이전과 동일한 ObjectDB 종료 경고가 남지만 실행은 정상 종료됐다. 이전 작업에서 변경 전 비교로 확인한 `sword_long_grip_test`의 어깨 정렬 실패는 이번에 재검증하거나 수정한 범위가 아니며, 근거는 이전 그레이박스 기록에 보존돼 있다.
