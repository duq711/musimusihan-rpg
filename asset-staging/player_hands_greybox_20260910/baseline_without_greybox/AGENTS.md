# 필수 완료 조건: 모든 기능을 테스트룸에 함께 추가

사용자 요구: **앞으로 생기는 모든 기능은 테스트룸에 추가합니다.**

새 게임 기능을 구현하거나 기존 기능의 동작을 확장할 때는 같은 변경에서 아래 세 가지를 모두 완료해야 합니다. 테스트룸 반영을 별도 후속 작업으로 미루지 않습니다.

1. `scripts/test_room_catalog.gd`에 해당 기능의 실행 가능한 시험 항목을 등록하거나 기존 항목을 확장합니다. 고유한 `id`, 올바른 분류, 실제 동작과 일치하는 설명, `action`과 필요한 `payload`를 제공합니다.
2. `scripts/test_room.gd`의 `run_feature()`에서 실제 플레이 코드·UI·장면으로 연결합니다. 필요한 시험 대상, 초기 상태, 이동 위치, 회복·재생성 수단도 준비합니다. 이름이나 설명만 추가한 항목, 게임과 별개로 결과를 흉내 내는 동작은 완료로 보지 않습니다.
3. `tests/`에 자동 검증을 추가하거나 확장하고 실행합니다. 카탈로그 등록뿐 아니라 해당 항목의 실제 효과, 관련 회귀 동작, 시험 상태의 격리·복원을 검증합니다. 조작이나 실행 방법이 달라지면 `TEST_ROOM.md`와 `README.md`도 함께 갱신합니다.

## 원본 카탈로그와 자동 등록

- 물품은 `ExpeditionInventory.ITEM_DEFINITIONS`에서 물품 탭과 시험 보급 상자에 자동 등록됩니다.
- 마법은 `SpellCatalog.ordered_spell_ids()`에서 마법 탭과 시험용 습득 목록에 자동 등록됩니다.
- 상태이상은 `ExpeditionSession.CONDITION_DRAIN_BONUSES`에서 생존 탭에 자동 등록됩니다.
- 위 유형은 원본 카탈로그를 확장하고 자동 등록 결과를 검증합니다. 같은 항목을 테스트룸에 중복으로 하드코딩하지 않습니다. 새로운 효과나 시전 유형이 추가되면 기존 범용 시험 동작으로 실제 사용 가능한지 확인하고 필요한 실행 경로와 검증도 추가합니다.
- 다른 신규 시스템은 명시적인 카탈로그 항목과 실행 동작을 추가합니다. 현재 미구현 효과를 지원하는 것처럼 표시하지 않습니다.

## 시험 세션 안전성

- 테스트룸 및 연결된 시험 장면은 `TestRoomSandbox`가 소유하는 별도 원정에서 실행합니다.
- 입장 시 `ExpeditionSession.capture_snapshot()`으로 기존 상태를 보존한 다음 `begin_new_journey()`로 시험 인벤토리를 분리합니다. 원본 인벤토리를 직접 시험용으로 변경하지 않습니다.
- 메인 메뉴로 돌아오면 보존한 상태를 복원합니다. 원본 인벤토리 참조와 연결된 신호를 유지하고, 나머지 변경 가능한 Dictionary는 깊은 복사합니다.
- `ExpeditionSession`에 새로운 상태 필드를 추가하면 같은 변경에서 `capture_snapshot()`과 `restore_snapshot()`, `tests/test_room_session_test.gd`를 반드시 확장합니다.
- 테스트룸 안의 `F2` 시험 메뉴, 연결 장면의 `F2` 복귀, 초기화, 사망·생환 후 재시험을 유지합니다. 시험 메뉴를 연 동안에는 전투와 생존 시간이 진행되지 않아야 합니다.

## 백그라운드 검증 기본값

- 자동 검증은 `tests/run_headless_tests.sh`를 Codex의 백그라운드 명령 세션에서 실행합니다. 실행기는 모든 `tests/*_test.gd`를 자동 발견해 각각 독립된 `--headless` Godot 프로세스로 차례로 돌리고, macOS에서 낮은 CPU·I/O 우선순위를 사용합니다. 통상적인 검증에서 편집기, 프로젝트 매니저, 게임 장면 또는 별도 Terminal 창을 실행하지 않습니다.
- 백그라운드 세션이 계속 도는 동안에도 창을 열지 않고, 완료 후 필요한 결과만 요약합니다. 검증이 끝나면 해당 검증이 시작한 Godot 프로세스가 남지 않았는지 확인하되, 사용자가 기존에 열어 둔 Godot 편집기·게임 프로세스는 종료하거나 조작하지 않습니다.
- `--headless`는 이 macOS Godot 빌드에서 더미 렌더러를 사용하므로 PNG 렌더링을 실제 화면 검증으로 간주하지 않습니다. UI·3D·실제 입력 변경은 헤드리스 자동 검증을 먼저 완료한 뒤 기존 `*_preview.gd` 하네스와 저장된 `artifacts/visual_qa/` 이미지로 확인합니다.
- 숨김·비활성 실행으로 완전한 검증이 가능한 프리뷰만 그 방식으로 실행합니다. `grab_focus()`, 마우스 캡처, `Input.warp_mouse()` 또는 인터랙티브 환경 변수를 쓰는 프리뷰는 사용자의 포커스·커서·소리를 방해할 수 있습니다. 이 경우 사용자 작업 중에는 실행하지 말고, 실행 전에 반드시 알리고 확인받습니다. `*_QA_INTERACTIVE=1` 모드는 자동으로 실행하지 않습니다.
