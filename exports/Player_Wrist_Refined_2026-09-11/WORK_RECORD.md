# 플레이어 손등–손목–팔 연결부 정리

사용자 요청: “이제 손등과 팔이 연결되는 지점의 부자연스러운 모델링을 디테일하게 다듬어주실래요?” 기존 양손 제작의 후속 작업으로, 앞서 승인된 Mac Blender 백그라운드 실행을 이어서 적용한다. 이번 시작 시 Blender 5.2.1 LTS의 실제 로컬 실행을 확인했으며 Blender MCP의 localhost:9876은 연결되지 않아 직접 백그라운드 제작한다.

## 문제와 수정 범위

이전 관절 모델의 손목 끝이 넓고 각지게 벌어져 있다. 게임에서는 손 표면이 손목 본에 고정된 채 별도 WristCuff 전체가 전완 방향으로 회전하므로, 손등과 팔 경계에 돌출부와 갑작스러운 꺾임이 생긴다. 중립 형상과 실제 팔 맞춤 변형을 함께 수정한다.

- 손목의 국소 표면을 좁히고 손등에서 자연스럽게 이어지는 테이퍼로 정리한다.
- 새 WristCuff를 충분히 나눈 얇은 중공 전이부로 제작하고 끝단을 부드럽게 마무리한다.
- 손 쪽 끝은 손에 고정하고 팔 쪽 끝은 실제 전완의 회전·길이를 따른다. 중심 경로와 단면을 함께 회전시키고 큰 굽힘에서는 안쪽만 연속적으로 눌리도록 한다. 바깥쪽과 굽힘에 수직인 폭은 유지한다.
- 새 메타데이터가 있는 상세 모델만 유연한 연결 변형을 사용한다. 원래 그레이박스와 기존 외형 동작은 유지한다.
- 손가락 30개 관절, 각 손의 교정 형상 15개, 손톱 형상·가중치, 16개 본의 기준 자세, 손목·장비 접촉 기준을 보존한다.

원본은 `../player_finger_joints_20260910/mac_output/iteration_02/`다. 이번 산출물은 `mac_output/`에 분리한다. 이전 관절·디테일 제작본과 납품 ZIP 등 328개 파일의 해시를 `baseline/preserved_artifacts.json`에 보존했다. 게임 파일과 관련 스크립트·시험은 `baseline/`에 복사했다.

## 테스트룸과 검증

기존 **캐릭터 그래픽 · 손가락 마디별 관절**에 **손목 옆면** 보기를 추가한다. 독립된 새 시험 메뉴나 새 전투 동작을 만들지 않고, 실제 상세 손·활·상자 시험에서 새 연결부를 사용한다. 마디별 조절, 손등·손바닥 보기, F2·재선택·초기화·종료 및 원정 복원을 유지한다.

`tools/verify_wrist_refinement.py`는 이전 Blender 원본과 비교해 변경이 손목 영역에 한정됐는지, 손가락·손톱·교정 데이터와 기존 본이 유지됐는지 검사한다. 새 연결부의 실제 형상과 GLB 왕복 좌표도 확인한다. Godot에서는 실제 메시의 손 쪽 고정·팔 쪽 추종, 바깥쪽·수직 폭의 보존과 안쪽의 연속적인 압축, 표면·노멀, 반복 업데이트·복원 및 실제 GPU 버퍼 반영을 검사한다. 창 없는 렌더러로 손등·손바닥·손목 옆면과 활·상자 자세를 검토한다.

## 최종 형상과 검증 진행

최종 모델은 `mac_output/iteration_02/`다. 1차 시안은 수치 검증 뒤 확대 렌더에서 13개 피부 정점의 돌출과 굽힘 시 전완 끝의 관통을 발견해 채택하지 않았다. 2차에서 손목 피부를 목표 단면에 직접 맞추고 전완 끝을 native z=0.075m부터 시작하도록 짧게 정리했다. z≥0.100m 영역은 좌우 5,098개·5,099개 정점에서 오차0으로 보존했다. 양손 모델은 각각 63,970삼각형·9메시다.

2차의 독립 Blender 검증은 `verify_02.log`와 `mac_output/iteration_02/verification_report.json`에서 통과했다. 손목 형상 변경은 왼손1,540개·오른손1,543개 정점에 한정되고, 손가락·손톱·웨이트·모든 교정 형상의 상대 변화량·16본 기준 자세는 보존했다. 새 연결부는 4,608정점·9,216삼각형의 폐합 중공 표면이며 비다양체·경계·퇴화 면이 없다. 양쪽 GLB 좌표와 편집 원본도 일치한다. 실제 Blender의 중립·굽힘 손등/손바닥/옆면 6장과 동일 카메라·조명 전후 비교 2장을 확인했다. 이전 원본328개 해시도 `preservation_verification.json`에서 통과했다.

첫 Godot 검사에서는 importer가 GLB custom property를 `extras` 사전에 저장하는데 런타임이 직접 메타데이터만 읽어 변형이 꺼져 있음을 발견했다. `godot_wrist_diagnostic02.log`의 실제 노드 출력으로 확인하고 양쪽 저장 형식을 읽도록 수정했다. 이 실패·진단 기록도 보존하며 최종 통과 기록과 구분한다.

활 당김·놓기와 상자 접촉의 큰 굽힘에서는 초기 중심 보간이 실제 면을 뒤집는 것을 발견했다. 팔 맞춤을 실제 손목 본 중심으로 보정하여 팔꿈치·손목을 고정하고, 중심 경로와 단면의 회전을 함께 계산하도록 수정했다. 8mm 양끝 회전 완화와 안쪽에만 적용하는 연속 탄성 압축을 사용한다. 실제 4,608정점/9,216삼각형을 이용한 독립 후보 계산에서 뒤집힘0, 양끝 오차6.1e−17m 미만, 가장 큰 굽힘의 전체 단면 폭74.2% 보존을 확인했다(`wrist_inner_curve_rational_8.0mm.json`). 이 수치 검사는 비인접 면 전체의 충돌 증명을 대신하지 않으므로 실제 Godot 화면도 별도로 확인한다.

## 최종 검증 완료

`godot_wrist_core02_elastic.log`에서 관절·상세 양손·그레이박스 3개, `godot_wrist_regressions02.log`에서 플레이어 팔·장비 접촉·상자 손·테스트룸 세션 4개가 모두 통과했다. 실제 손목 본과 팔꿈치 고정, 양끝 접합, 바깥쪽·수직 폭 보존, 안쪽의 단조 압축, 실제 삼각형 방향·정점 Jacobian·법선, 손가락30관절·UI·반복·복원 검사를 포함한다.

창 없는 실제 Forward+/Vulkan 렌더러에서 `player_finger_joints/wrist_final_02/` 10장과 `player_hands_detailed/wrist_final_02/` 6장을 생성하여 전부 확인했다. 각 손목4,608정점, 총92,160개 정점 표본의 GPU readback 위치 오차0m, 법선 오차 최대0.00012760, 부정상 접선/정점0이었다. 가장 큰 굽힘의 실제 Jacobian 최솟값은0.016112로 양수다. 양쪽 캡처 기록의 원정·인벤토리·커서 및 소스 보존도 통과했다.

최종 산출물은 `exports/Player_Wrist_Refined_2026-09-11/`과 같은 이름 ZIP이다. 전후 비교·Blender/GLB·16개 실제 Godot 화면·제작/런타임/검증 소스·결과를 포함한다. `validation_summary.json`에 상세 근거와 범위를 기록했다. 기존 fixture 종료의 ObjectDB2개 경고와 비실패 debug script 경고는 로그에 남으며 기능 실패는 없다. 관련 없는 전체 시험 묶음과 비인접 면의 전역 충돌 증명은 실행하지 않았다.
