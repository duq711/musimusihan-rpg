# 영상 기준 1인칭 모션 — MacBook 제작

참고: https://youtu.be/sU7jk2OQlgc (First Person Sword and Shield animations for UE4).
로컬에 보존된 동일 영상과 실제 디코딩 프레임을 열어 걷기·달리기·점프·공격을 비교했다. 원본의 걸음/달리기 입력 표시는 없으므로 두 속도의 구분은 게임의 실제 걷기/질주 속도에 맞춘 해석이다.

## 적용 내용

- `godot-game/assets/animations/reference_sword_motion/motion_manifest.json`: Mac Blender 5.2.1에서 만든 대기·걷기·달리기·도약·공중·착지·우측 대각·좌측 역베기·내려베기 9클립. 손·검·방패와 오른팔 관절을 120Hz로 저장했다.
- `scripts/player.gd`: 걷기 클립 연결, 속도별 혼합, 실제 바닥 접촉에 따른 착지, 전체 클립에 중복 적용되던 대기 위치 보정 제거, 검격 취소 후 대기로 회복, 방패 가드 때 작은 쇄골 전진/하강.
- `scripts/reference_sword_motion.gd`: Mac 제작 출처 검증, 간격이 다른 타격 키에서 각속도가 꺾이지 않는 구면 베지어 보간. 기존 전투 타격 시점 유지.
- `scripts/sword_shield_choreography.gd`: 기존 낮은 중앙 방패 가드의 양 끝 자세를 유지하며 중간 들기 경로를 팔 가까이 조정.
- `scripts/test_room_catalog.gd`, `scripts/test_room.gd`: 기존 영상 모션 시험의 걷기·달리기 안내와 실제 동작 유지. 테스트룸 자동 검사에 실제 걷기·보폭 재생·정지 검증 추가.

제작 원본: `asset-staging/reference_motion_mac_20260912/iteration_05/FirstPerson_Motion_Controls.blend`. 장비/손/관절 제어 궤적을 저장한 파일이며, 사용자가 열어 둔 양손 직접편집 Blender 파일은 수정하거나 다시 열지 않았다. 제공된 검·장갑·소매 원본 GLB도 변경하지 않았다.

## 비교와 반복

1차에서 대기·도약·공중·착지·세 베기의 방향을 만들었다. 2차에서 중간 키마다 멈추던 속도 곡선과 넓은 준비 동작을 수정했다. 3–4차에서 타격 키의 각속도 불연속과 방패 위팔의 과도한 길이를 수정했다. 5차에서 원본 비교상 약했던 착지 때 검의 전방 숙임을 강화했다.

최종 검토 자료: `godot-game/artifacts/visual_qa/reference_sword_motion/mac_verified_05/`의 MP4, 7개 전체 PNG 시퀀스, 동작별 연락표와 참고 영상 비교 이미지. 중간 결과와 수정 전 렌더는 같은 상위 폴더의 `mac_rebuild_before`, `mac_rebuild_01`, `mac_rebuild_02`, `mac_rebuild_final`에 별도로 보존한다. 생성 이미지나 평면 합성으로 실제 게임 렌더를 대체하지 않았다. 비교용 연락표는 실제 원본 프레임과 실제 Godot 프레임을 나란히 배치한 검수 자료다.

최근 방패 가드 유지 검토: `godot-game/artifacts/visual_qa/sword_shield/reference_motion_guard_verified/`의 대기·가드·피격·반격 화면. 이 캡처 뒤에는 착지 클립 하나만 변경됐으며 나머지 8클립이 바이트 내용 기준 동일함을 확인했다.

## 검사 근거

최종 로그는 이 폴더의 `landing_final_checks.log`, `integration_final.log`, `final_checks.log`, `render_verified_05.log`, `guard_verified_render.log`다. 자동 검사는 모두 공식 헤드리스 실행기로, GPU 검토는 창·키 입력·마우스 캡처 없이 Mac embedded Vulkan 렌더러로 실행했다. 원정/가방/커서 상태 보존과 실제 표적 타격·충돌·기력 비용·F2 반복을 확인한다.

오래된 검사의 “모든 공격 중 손이 항상 화면 안에 있어야 한다”, “모든 자세에서 어깨가 원본 대기 위치에 고정돼야 한다”는 조건은 이번 참고 영상 및 관절 애니메이션과 충돌하므로, 실제 손-검 접촉·피부/소매 연결·팔 길이·대기 복귀·가드 모서리 구도를 검사하도록 바꿨다. 물리적인 접촉/길이/속도 오차 허용치는 완화하지 않았다. 구면 보간 변경 후 타격 전후 각속도 차이는 세 베기 모두 0.043rad/s 미만이다. 120Hz 검격·가드 검사에서 방패 위팔 최대 길이는 0.487m, 전완은 0.340m, 관절 연결 오차는 0.0005mm 미만이었다.

## 확인 범위와 한계

현재 게임의 세 방향 베기를 대상으로 했다. 원본 영상 후반의 찌르기 및 별도 연속 콤보를 새 전투 기능으로 추가하지는 않았다. 원본 모션 캡처를 복원한 것이 아니며, 화면 밖의 깊이·어깨/팔꿈치 위치는 현재 장비와 팔 구조에 맞춰 제작했다. 프레임별 완전 일치나 객관적 유사도 퍼센트는 주장하지 않는다.

전투의 최소 준비 0.22초, 양손 타격 시점 0.145초, 활성 0.30초 및 기존 회수 시간은 유지한다. 따라서 영상과 전체 재생 시간이 동일하지 않으며, 길게 누르는 준비 동작은 플레이어 입력에 따라 달라진다. 게임 카메라 FOV, 손·장비의 디자인과 UI는 변경하지 않았다.

GPU 영상은 현재 프로젝트의 실제 플레이어·재질·모델·이동/전투 코드로 만든 격리 검수 장면이다. 이미 실행 중인 사용자의 동굴 게임 창을 재시작하거나 그 창에서 키보드 조작한 것은 아니다. 직접 플레이 체감과 모든 던전 조명에서의 외형은 미확인이다. 테스트룸 종료 시 기존 ObjectDB 2개 누수 경고는 남지만 검사 실패/게임 저장 변조는 없었다.

## 최종 결과

최종 5차 렌더는 Vulkan 60fps, 7개 실제 동작 시퀀스 541프레임으로 완료했다. PNG에서 만든 MP4도 다시 디코딩해 541프레임임을 확인했다. 마지막 착지·달리기·양방향 베기 및 원본 비교 이미지를 직접 열어 검토했다. 관련 자동 검사 7종이 통과했으며, 렌더 중 원본 파일·원정·커서 상태 보존 검사도 통과했다. 최종 파일 해시는 `final_source_hashes.json`, 결과 요약은 `validation_summary.json`에 보존했다.
