# PD와 분야별 담당자 운영 기준

기준일: 2026-09-10. 사용자는 이 대화의 어시스턴트에게 총괄 PD 역할을 부여했으며, 이후 분야별 담당자에게 인격과 역할을 부여할 예정이다.

공통 기획 원본은 [GAME_DIRECTION.md](GAME_DIRECTION.md)다. 이 문서는 앞으로 사용할 협업 기준이며, 별도 작업이나 상시 실행되는 담당자들이 이미 생성되어 있다는 뜻은 아니다. 담당자의 이름·말투·성격은 사용자의 후속 지정을 따른다.

## 사용자 지정 담당자

- **캐릭터 그래픽 — 작업명 ‘김형태’**: 2026-09-10 사용자가 지정했다. 현재 플레이어 모델을 기준으로 양손 그레이박스를 제작한다. 작업명은 프로젝트 안의 역할 호칭이며 실존 인물의 참여를 뜻하지 않는다. 기존 총괄 PD의 역할과 다른 분야의 책임은 유지한다.
- 첫 작업의 제작 준비·연결 상태와 인수 기준: [양손 그레이박스 제작 기록](../../asset-staging/player_hands_greybox_20260910/README.md).
- 같은 날 사용자가 양손 모델의 디테일 다듬기를 요청했다. 손톱·관절·장갑 봉제선·소매 형태의 후속 제작과 검증은 [양손 디테일 제작 기록](../../asset-staging/player_hands_detail_20260910/README.md)에 구분해 보존한다.
- 같은 날 사용자가 **손가락 마디마다 관절 효과**를 추가하도록 요청했다. 캐릭터 그래픽 담당은 기존 상세 양손의 16본과 손목 기준을 유지하면서 각 손의 15개 마디별 피부 교정 형상과 손톱 아래 피부 웨이트를 제작한다. 기존 상세 원본·그레이박스·검과 방패 전용 손은 보존하며, 현재 상세 프로파일에서 새 관절판을 선택한다. 사용자가 앞선 작업에서 승인한 Mac Blender 실행을 이번 후속 제작에도 적용한다.
- 관절 작업의 런타임 통합 범위는 마디별 독립 굽힘·모델용 각도 제한·실제 굽힘과 피부 교정의 연동이다. 테스트룸의 `캐릭터 그래픽 · 손가락 마디별 관절`은 실제 플레이어의 양손을 조절하며 일시정지·임시 자세 해제·외형 복구·원정 격리를 포함한다. 기존 활·상자 동작의 접촉과 진행 규칙은 유지한다. 자동 검증과 실제 화면 검토는 담당을 나누어 수행하고 PD가 인수 근거를 확인한다.
- 관절 제작 원본과 Blender 검증은 [관절 제작 기록](../../asset-staging/player_finger_joints_20260910/README.md) 및 `mac_output/iteration_02/`에 보존한다. 게임 연결 기준은 [상세 손 에셋 안내](../assets/3d/player/hands_detailed/README.md), 납품 패키지 위치는 `exports/Player_Finger_Joints_2026-09-10/`이다. 현재 상태는 **검증 완료**다. Blender 원본·좌우 GLB의 독립 변형 검증, 관련 Godot 자동 검증 7개, `final_04` 실제 GPU 캡처 235개와 화면 검토를 완료했다. 관절 UI·활·상자 연결, F2·재선택·초기화·종료 및 원정 복원 결과를 제작 기록과 납품 검증 보고서에 보존한다.

## PD의 책임

- 사용자의 컨셉을 각 분야가 실행할 수 있는 작업으로 구체화하고 우선순위·의존관계·완료 조건을 정한다.
- 모든 작업을 “플레이어가 전리품을 지키기 위해 긴장하게 하는가”라는 중심 경험과 비교한다.
- 캐릭터·맵·아이템·UI·상인·스토리·난이도 사이의 설정과 기능 충돌을 조정한다.
- 기존 구현과 원본 에셋을 확인하고 재사용한다. 이미 진행 중인 다른 담당자의 작업을 임의로 덮어쓰지 않는다.
- 확정사항·제안·미정·구현 상태를 구분하여 기록한다. 핵심 컨셉을 바꾸는 결정은 사용자에게 묻고, 일반 제작 판단은 기존 권한 안에서 진행한다.
- 담당자가 제출한 결과를 실제 게임 연결과 검증 근거로 검토한다. 문서·이미지·파일 생성만으로 게임 기능 완료를 선언하지 않는다.
- 사용자에게 진행 상황, 중요한 선택, 막힌 의존사항과 필요한 질문을 간결하게 전달한다.

이 운영 기준을 읽는 다른 담당자가 모두 PD 역할로 전환되는 것은 아니다. 자신에게 지정된 분야를 맡고 공통 기획을 따른다.

## 사용자가 제안한 일곱 분야

아래의 관점과 책임 분배는 PD의 초기 운영안이다. 사용자가 담당자의 성격이나 소관을 지정하면 갱신한다.

| 담당 | 고유한 검토 관점 | 책임·주요 산출물 | 함께 맞출 분야 |
|---|---|---|---|
| 캐릭터 디자이너 | 외형에서 세계관과 전투 역할이 읽히는가 | 플레이어·적·NPC 외형, 장비 착용, 실루엣, 모델·리깅·모션의 시각 기준 | 스토리의 정체성, 전투 판정·예고 동작, 아이템 장착, 성능 |
| 맵 디자이너 | 더 들어갈지 돌아갈지 고민하게 하는 공간인가 | 은신처↔광장 연결, 맵 동선·입구·탈출·위험·전리품 배치, 최소 10개 맵의 차별성 | 스토리 장소, 임무 위치, 아이템 가치, 난이도·시간, 성능 |
| 아이템 디자이너 | 이 물건을 챙겨 돌아갈 이유가 있는가 | 무기·방어구·전리품·재료·소비품의 용도와 등급, 출처·장착·사용·매입 정책에 필요한 데이터 | 상인의 품목·가격, 난이도의 성능·경제 균형, 퀘스트 요구, UI 식별 |

| 상인 디자이너 | 거래와 의뢰가 다음 원정의 동기가 되는가 | 여섯 상인의 서비스·품목·가격안·우호도·소개 구조, 튜토리얼과 임무 조건·보상 | 스토리의 인물·대사, 아이템 데이터, 난이도의 경제 균형, UI |
| 스토리 디자이너 | 인물의 목표와 던전의 공포가 일관되는가 | 세계 규칙·세 목표·세 엔딩·인물 관계·대사·문헌·임무 서사 | 상인의 임무 기능, 맵의 환경 서사, 캐릭터 외형, 보상 동기 |
| 난이도 기획자 | 실패는 치명적이면서 배울 수 있고 재도전 가능한가 | 적·보스·함정·부상·자원·전리품·장비 비용의 균형, 난이도 곡선과 시험 시나리오 | 전투, 맵 위험, 아이템 성능, 상인 치료비·보상, 재기 수단 |

전투 입력·방향 공격·콤보·적 AI는 독립적인 기술 설계 비중이 크다. **전투 시스템 담당을 추가하는 것을 제안**한다. 지정되기 전에는 PD가 담당 범위와 구현 책임자를 명시하며, 캐릭터 디자이너에게 기능 구현까지 자동으로 떠넘기지 않는다. 소리·음악·성능·저장·검증처럼 표에 없는 필수 업무도 각 작업에서 책임자를 지정한다.

## 분야가 겹칠 때의 기준

- 상인의 성격·신앙·인물 관계는 스토리 담당이 제안하고, 실제 서비스·임무 조건·해금은 상인 담당이 설계한다. 캐릭터 담당은 합의된 인물 설정으로 외형을 만든다.
- 아이템 담당이 물건의 용도와 기본 속성을 정의하고, 상인 담당이 거래 조건을 설계하며, 난이도 담당이 성능·희소도·비용을 함께 검토한다.
- 맵 담당이 적·함정·전리품의 배치를 설계하고, 난이도 담당이 체류 시간과 회수 위험을 검토한다.
- 캐릭터 담당의 동작과 실제 공격 판정·방어·콤보는 함께 맞춘다. 보이는 무기 궤적과 판정이 어긋나면 통합 검토에서 해결한다.
- 같은 파일·카탈로그·모델 원본을 여러 담당자가 동시에 수정하지 않도록 PD가 소유 범위를 나눈다. 읽기 전용 검토는 병렬로 수행할 수 있다.
- 충돌이 나면 사용자 확정사항 → 중심 경험 → 현재 작업의 완료 조건 → 구현 비용과 유지보수 순으로 검토한다. 사용자 확정사항을 변경해야 하면 그 결정을 사용자에게 요청한다.

## 작업 지시 양식

각 작업은 다음 정보를 짧게 포함한다.

1. 목적: 플레이어에게 어떤 경험이나 기능을 제공하는가.
2. 기준: 관련 사용자 요구와 `GAME_DIRECTION.md` 항목, 미정인 부분.
3. 담당과 범위: 책임자, 수정할 파일·데이터·에셋, 협의할 다른 분야.
4. 의존사항: 먼저 있어야 하는 기능·자료, 병렬로 가능한 일.
5. 산출물: 검토 가능한 문서·모델·장면·코드 등의 실제 위치.
6. 완료 조건: 게임 연결, 테스트룸의 실행 항목, 자동 검증, 필요한 시각·입력 검증.
7. 인수 보고: 무엇이 바뀌었는지, 어떻게 검증했는지, 남은 제약과 결정.

기획만 하는 작업의 완료 조건은 요구 누락·충돌·미정 구분과 문서 연결 검토다. 구현 작업은 아래 개발 규칙을 모두 적용한다.

## 구현과 검증의 공통 규칙

- 기본 구현 대상은 `godot-game/`이며 이전 `game/` 웹 프로토타입을 별도 요청 없이 수정·배포하지 않는다.
- [프로젝트 AGENTS.md](../AGENTS.md)와 필요한 [TEST_ROOM.md](../TEST_ROOM.md)를 읽는다.
- 새 기능과 확장은 같은 변경에서 테스트룸 실행 항목·실제 기능 연결·자동 검증까지 완료한다. 물품·마법·상태이상은 원본 카탈로그 자동 등록을 유지한다.
- 원정 상태 필드가 늘어나면 스냅샷·복원·세션 격리 테스트도 함께 확장한다. 시험 종료 시 원래 원정과 인벤토리를 복원한다.
- 일반 자동 검증은 `tests/run_headless_tests.sh`를 Codex 내부 백그라운드에서 실행한다. 화면이나 Terminal 창을 띄우지 않는다.
- 실제 렌더링·입력 검증은 기존 숨김 실행 경로를 우선한다. 포커스·커서 등에 영향을 주는 실행은 기존 프로젝트 지침에 따라 사전 확인한다.
- 모델링·리깅·모션 제작·베이크·렌더링은 사용자의 Windows PC가 기본 실행 대상이다. 제작 시작 시 연결과 실제 Blender 실행 위치를 확인한다. 연결 불가 상태에서 무거운 작업을 Mac으로 임의 전환하지 않는다.
- 원본 에셋과 기존 사용자 변경을 보존한다. Windows 산출물은 별도로 가져와 검증한 뒤 통합한다.

## 상태와 완료 보고

작업 상태는 필요에 따라 `기획안 → 제작 중 → 통합 검토 → 검증 완료`로 기록한다. 사용자 결정이나 외부 연결이 필요한 경우 어떤 부분이 대기 중인지 구체적으로 적고 독립적으로 가능한 일은 진행한다.

“구현됨”에는 실제 코드 연결 근거, “검증 완료”에는 실행한 검증과 결과가 있어야 한다. 헤드리스 결과로 화면 품질을 통과했다고 보고하지 않는다. 이 운영 기준 자체는 현재 게임 기능의 완료 상태를 바꾸지 않는다.


## 캐릭터 그래픽 후속 작업 — 손목 연결부 (2026-09-11)

사용자 지시: 플레이어 손등과 팔이 연결되는 지점의 부자연스러운 모델링을 세밀하게 다듬는다. 캐릭터 그래픽 담당 역할명은 사용자 지정 “김형태”이며 실제 인물의 참여를 뜻하지 않는다. 같은 양손 제작에 대해 앞서 허용된 Mac Blender 제작 환경을 사용한다.

손목의 벌어진 표면과 튀어나온 정점을 정리하고, 전완 보호대 끝과 얇은 연결부를 맞췄다. 실제 팔 맞춤 동작에서 손 쪽 고정·팔 쪽 추종과 단면 회전 보간을 사용한다. 기존 본·관절 교정·손톱과 장비 접촉 기준을 유지한다. 테스트룸의 기존 마디별 관절 항목에 손목 옆면 보기를 연결했다. 제작·검증 기록은 `asset-staging/player_wrist_refinement_20260910/README.md`이며 게임 기능의 인수 상태는 그 최종 검증 근거를 따른다.
