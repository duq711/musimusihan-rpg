# 사진 기준 플레이어 양손 재제작

사용자가 이전 피부색 제작본은 현실적이지 않다고 지적하며 첨부한 손바닥·손등 사진과 비슷하게 다시 제작하도록 요청했다. 이번 작업은 사진처럼 맨손으로 제작했다. 사진 원본은 `reference/user_hand_photo.png`에 그대로 보존했다. 이전의 수치 검증과 사진에 대한 외형 비교는 별개로 취급했다.

최종 모델은 `mac_output/final_04/`의 `bilateral_hands_reference.blend`, `left_hand_reference.glb`, `right_hand_reference.glb`다. 실제 Godot 상세 손의 기존 두 경로에 같은 GLB를 연결했다. 배포 위치는 `exports/Player_Hands_Photo_Reference_2026-09-11/`와 같은 이름의 ZIP이다. 최종 근거는 `validation_summary.json` 및 `package_verification.json`을 따른다.

## 형태와 피부

손가락의 굵기를 줄이고 마디 사이에서 가늘어지는 단면·손끝 살집을 만들었다. 손가락 사이의 U자 곡면과 엄지 뿌리, 손바닥의 두 살집과 중앙 오목함, 낮게 드러나는 손등 힘줄, 손목의 폭과 두께를 정리했다. 피부가 칠해진 실제 연속 표면12,036개 정점을 유지하고, 별도로 붙어 있던 봉제선·장갑 장식2,952개 정점을 제거했다. 손바닥의 장갑색도 피부 재질로 바꿨다.

원래16본의 기준 행렬·손목 위치를 유지하고, 중립과15개 마디 교정 형상에 같은 해부학적 형태 변환을 적용했다. 손톱은 얇고 짧은 곡면으로 다시 만들고 각 말단 본에 묶었다. 최종 손톱은 각1,538개 정점의 촘촘한 삼각형 표면이며, 면 안쪽까지 실제 피부와 맞닿는 위치를 검사했다.

밝은 베이지 피부에 옅은 혈색을 넣었다. 손바닥·손등 중앙과 각 손가락의 좌표에 실제 사진의 색 변화를 맞추고 최대65% 혼합했다. 손가락 사이와 피부 밖의 흰 배경은 투영 범위와 부드러운 전환으로 배제했다. 손금·마디 주름·손목 주름·미세결은 절차적 재질로 만들고 실제 tangent normal에도 베이크했다. 공유4096×4096 base color·normal·roughness3장을 사용하며 원래 사진 파일은 편집하지 않았다.

`ReferenceUV`로 새로 펼쳐 실제 Cycles에서 굽고, 빈 atlas 여백을 가까운 유효 픽셀로 채웠다. 색과 거칠기의 아주 옅은 경계 픽셀은 감마·양자화 차이가 있으므로 두 맵의 유효 영역 합집합을 보존했다. 기존 표면 픽셀은 바이트 단위로 유지하며 빈 영역에만 padding을 적용한다. 베이크용 임시 속성은 제거해 게임에서 이중 착색되지 않게 했다. 텍스처는 `.blend`와 GLB 모두에 내장했다.

## 후보 검토와 수정 근거

- `geometry_01`~`geometry_03`: 세 방향 실제 clay 렌더로 손가락·손목·web 곡면을 비교했다. 1µm 반올림 격자로 동일 정점을 묶던 방식의 작은 균열은 실제 거리 기반 결합으로 해결했다. 이전 파일은 보존했다.
- `lookdev_01`~`lookdev_06`: 실제 모델 렌더로 피부색과 주름을 조정했다. 사진의 흰 윤곽이 피부에 묻어 나오던 후보는 제외하고, 최종에서는 중앙 손바닥과 손가락의 안전한 범위에만 사진을 사용한다.
- `final_01`: 실제 베이크·근접 렌더와 독립 검사에서 듬성한 손톱 면이 피부 안으로 들어가는 문제를 발견해 납품 후보에서 제외했다. 첫 padding 실패도 `bake_attempt_01`과 로그에 남겼다.
- `geometry_04`: 손톱10개를 다시 분할·투영했다. 손목 아래의 얇은 선은 피부 끝과 연결부가 실제로 겹치는 문제였다. Cuff의 native y[−25,0]mm 안에서 바깥320정점만 최대0.35mm 보정했다. 피부·15개 키·웨이트·16본과 손목의 팔 쪽 고정 구간은 유지했다.
- `final_02`: geometry04에 최종 재질을 새로 굽고 양손 GLB와 편집 원본, 실제 검토 렌더6장을 다시 만들었다. 손톱의 피부 침투와 손목 아래 겹침선이 사라진 것을 직접 확인했다.

- `geometry_05` / `final_03`: final02의 첫 실제 GPU 화면에서 손목 굽힘 때 연결부가 약13mm 파이는 문제를 발견해 해당 게임 캡처는 승인하지 않았다. 피부 끝(z≈20.7mm)이 변형 구간 안에 있었으므로 Cuff의 변형 시작만14→28mm로 옮겼다. 끝75mm·버전1·모든 형상·웨이트·재질을 유지하고, GLB 전체 BIN 데이터가 동일함을 확인했다. 정지 Blender 화면에 영향을 주지 않는 메타데이터 수정이므로 기존6렌더는 동일 해시로 복사했다. 보존 근거는 `final_03/metadata_update_report.json`이다.

- `geometry_06` / `final_04`: 추가한 실제 접합 검사에서 엄지 최대 굽힘·주먹 때 약2.2mm 틈을 확인했다. 피부 끝에 남아 있던 엄지 영향을 Godot z10–18mm의 smoothstep으로 손목 본에 넘기고18mm 이후는 손목 본에 고정했다. 나머지 웨이트·형상·교정키·텍스처는 유지한다. Cuff 시작은26mm로 미세 조정하여 피부 끝보다5.3mm 여유를 두고, 기존 안쪽 압축 하한0.45도 유지했다. 실패 기록은 `godot_reference_final02_weight_gap_failure.log`에 보존했다.

## 검증과 통합

최종 독립 Blender 검사는 `verify_reference_final04.log`와 `final_04/verification_report.json`에서 통과했다. 손목 웨이트의 승인된 보정식과 그 밖의 원본 웨이트,16본,15개 교정, 관절·손톱, 승인 형상, 손목 보호 구간, PBR·UV·접선 및 양 GLB 왕복을 확인했다. 손톱의 실제 표면 간격 최대는 약0.303mm이고 노출된 윗면의 최소 여유는 약0.055mm다. 편집 파일과 GLB 모두에서 중립·개별 마디·주먹·원복을 확인했다.

final02의 기존7개 헤드리스 검사는 통과했으나 수치 통과만으로 실제 손목 연결을 승인하지 않았다. final04에서는 실제 현재 포즈의 피부 경계와 Cuff 표면 간격을 재는 검사를 추가하여 관련7개 항목(player_finger_joints/player_hands_detailed/player_hands_greybox/player_arm/weapon_hand_contacts/chest_hands/test_room_session)을 다시 실행해 모두 통과했다. 최종 실행 기록은 `godot_reference_final03.log`다. 다른 손가락의 가중치가 없는 정점의 교정 변위는 실제 imported30키에서 정확히0이다. 피부 연결성·실제 PBR·손목 변형·활과 상자·UI·원정 복구를 확인했다. 기존 일부 시각 시험의 ObjectDB 종료 경고는 로그에 그대로 기록했다.

기존 `detailed` 프로파일과 테스트룸 → 기본 → **캐릭터 그래픽 · 사진 참고 맨손**, **캐릭터 그래픽 · 손가락 마디별 관절**에 연결한다. 게임 초기 외형과 기본 검·방패 전용 손은 기존대로다. 실제 화면 검토는 별도 창을 열지 않는 embedded Vulkan 하네스를 사용한다. 최종18장 검토 상태와 각 소스·화면 해시는 `validation_summary.json`에 기록한다.

실제 embedded Vulkan18장도 상태 검사를 통과하고 직접 검토했다. 주먹 접합의 실제 표면 간격은 최대 약0.405mm이며 자세가 바뀌어도 유지된다. 이전 배경색 파임은 사라졌다. 단, 강한 손목 굽힘에서는 피부/Cuff 경계의 얕은 단차가 남는다. 이를 단순 조명이나 완전한 사실적 표현으로 설명하지 않는다. `visual_review.json`에 위치와 한계를 기록했다.

## 실행 위치와 보존

같은 양손 작업에서 앞서 허용된 Mac Blender5.2.1LTS 백그라운드 실행을 계속 사용했다. 시작 시 MCP localhost9876 연결은 불가했으며 실제 Blender 실행 위치를 따로 확인했다. 사용자 편집기 창을 조작하거나 검증용 게임·Terminal 창을 띄우지 않았다.

기준 원본은 `../player_hands_realism_20260911/mac_output/iteration_04/bilateral_hands_realistic.blend`다. 이전 제작·검증·납품 파일1,888개는 `baseline/preserved_artifacts.json`의 해시로 보존한다. Godot 교체 전 파일은 별도 baseline에도 보관했다. 재현 순서와 외부 기준 자료, Blender 사용법은 `DELIVERY_README.md`를 따른다.
