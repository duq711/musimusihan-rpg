# 플레이어 양손 피부색·주름·골격 디테일

2026-09-11 사용자 요청: “이제 실제 손처럼 유사하게 색을 칠해주시고 주름과 골격같은 디테일적 요소를 강화해주세요.” 기존 손목 연결 정리본을 기반으로 실제 피부색·손톱·가죽·누비소매의 PBR 재질과 손가락 주름·마디 돌출·손등 힘줄의 섬세한 형상을 강화한다. 현재 반장갑과 플레이어의 복식 형태를 유지하며 골격은 피부 아래 형태로 표현한다.

이 양손 작업에서 앞서 허용된 Mac Blender 제작을 계속 적용한다. 이번 시작 시 실제 로컬 Blender5.2.1LTS를 확인했다. MCP localhost:9876는 연결 불가이므로 백그라운드 Blender를 직접 실행한다. 원본 player_gravebound의 어두운 흑갈색 가죽·회갈색 누비소매와 중간 밝기의 따뜻한 피부를 참고한다.

기준 원본은 `../player_wrist_refinement_20260910/mac_output/iteration_02/`다. 새 원본·게임용 GLB·텍스처·실제 렌더는 `mac_output/`에 별도로 저장한다. 원본 손가락16본·15개 피부 교정 형상·스킨 웨이트·손톱 접촉·손목과 전완의 접합 형상은 보존한다. 미세한 피부/장갑 형상 변경은 모든 shape key에 같은 양을 적용해 기존 관절 교정 변화량을 유지한다.

실제 게임용 GLB에서 동작하는 base color·normal·roughness 텍스처를 제작하고 Blender 원본에 pack/GLB에 embed한다. Blender 전용 셰이더의 미리보기로 완료 처리하지 않는다. 기존 테스트룸의 양손 디테일·마디별 관절 항목에서 재질과 형태를 검토하며 실제 활·상자·손목 변형, 기존원정 복원을 검증한다. 자동 검증은 지정 headless 실행기, 실제 화면은 창 없는 embedded renderer를 사용한다.

제작·독립 원본 검증·Godot 시험을 분담했다. 최종 채택 모델은 `mac_output/iteration_04/`이며 현재 Godot의 상세 손 모델에도 동일한 GLB를 연결했다. 아래에 제작 과정과 최종 인수 근거를 구분한다.

## 제작 중 발견과 수정

- 기존 UV에는 겹침·음수 범위·영면적 면이 있고 손톱에는 UV가 없었다. 모든 표면에 새 `RealismUV`를 만들고 양손 공용 4K atlas의 색·노멀·거칠기를 굽는다.
- 첫 실행은 색 채널 저장 후 통계 수집을 비효율적으로 반복 읽어 중단했다. 배열 일괄 읽기로 수정했으며 `iteration_01`은 미완성 기록이다.
- `iteration_02`의 실제 확대 렌더에서 피부색·손톱색은 확인했으나 피부 주름 가독성이 부족해 채택하지 않았다. 작은 장식 UV의 여백 비용으로 손의 실사용 해상도가 부족했다. 다음 후보에서 피부에 UV 면적을 재배분하고 마디 주름 베이크를 보강한다.
- 임시 색상 정점 속성은 베이크 후 지워 glTF의 정점색과 텍스처가 곱해지는 이중 착색을 방지한다. 노멀맵에 맞는 UV 접선을 내보내고 Godot 원본 메시에서 직접 검사한다.
- `iteration_03`은 손마다 atlas 면적을 약2.87%에서16.40%로 늘렸다. PIP/DIP의 국소 좌표로 주름을 픽셀 단위 계산해 얕은 호형 주름이 실제 노멀맵에 남도록 했다. 손등 확대·손바닥 확대·굽힘 렌더에서 색과 주름 가독성을 직접 확인했다.
- 왼쪽 전완의 내보낸 접선 한 개가 길이0인 것을 독립 검증과 GLB 바이너리 검사로 찾았다. 영면적이 아닌 실제 인접 두 삼각형의 UV 미분을 면적 가중한 뒤 원래 법선 평면에 투영해 접선만 복원했다. 수정은12바이트이며 기하·UV·본·웨이트·재질과 다른 바이트는 모두 그대로다. 근거는 `diagnostics/tangent_repair_report.json`이다.
- 원본 편집 파일의 매우 작은 스킨 가중치 일부는 Blender glTF 내보내기의 `min_influence=0.0001` 규칙 때문에 GLB에서 생략된다. 이전 손목 GLB에도 같은 변환이 적용돼 있었다. 편집 원본끼리는 가중치 정확 보존을, 게임 GLB끼리는 이전 GLB 가중치 보존을 각각 검사하며 이번 제작에서 새로 생긴 차이로 오인하지 않는다.
- `iteration_03`은 독립 Blender 검사와 Godot 자동 검사7개, 실제 GPU18컷의 상태·메시 검사를 통과했다. 그러나 직접 화면 검토에서 중거리 손가락에 다각형의 검은 선과 장갑의 흰 반사 경계가 보여 시각 인수는 보류했다. 수치 통과를 최종 외형 통과로 취급하지 않았다.
- 같은 실제 게임 자세·카메라·조명을 유지한 진단 두 컷에서 노멀맵만 꺼도 오류가 남았고, 노멀맵을 켠 채 색·거칠기만 상수로 바꾸면 사라졌다. 색과 거칠기 atlas의 약49.615%를 차지한 검은 빈 영역이 축소 필터에 섞이는 원인을 확인했다. 노멀 배경은 이미 정상 중립색이었다. `diagnostics/normal_off_open_01/`, `diagnostics/color_roughness_constant_open_01/`, `diagnostics/atlas_background_stats03.json`에 근거를 보존한다. 새 `iteration_04`에서는 기하·UV·유효 텍스처 픽셀을 유지하고 빈 여백만 보정한다.

## 최종 채택과 게임 연결

`iteration_04`는 기존 유효 픽셀8,453,226개를 세 텍스처 모두 정확히 보존하고, 빈 여백8,323,990개를 가장 가까운 유효 경계 값으로 채웠다. 기존 주름과 색의 해상도를 유지하면서 실제 게임 거리에서 검은 다각형 금과 장갑의 흰 반사 경계가 사라진 것을 직접 확인했다. 원본 형상·관절·UV·재질 바인딩은03과 같다.

최종 Blender 원본은 텍스처를 내장하며 열면 재질과 양손 카메라를 바로 확인할 수 있다. 기본 렌더는1600×1300,24샘플과 denoise를 사용한다. 실제 최종 렌더 `bilateral_dorsum.png`, `preview_finger_dorsum.png`, `finger_palm_closeup.png`와 같은 카메라의 전후 비교2장을 보존한다. 전후 비교의 after는 최종 손등 확대 이미지와 같다.

Godot의 `assets/3d/player/hands_detailed/` 좌우 GLB는04 파일과 바이트 단위로 같다. 기존 상세 손과 마디별 관절 테스트룸 항목에서 피부색·손톱·주름과 힘줄을 확인한다. 게임 초기 외형 선택과 기존 손목 변형 코드는 그대로이며, 이번 변경은 상세 손 에셋과 그 재질 검증을 확장한다.
