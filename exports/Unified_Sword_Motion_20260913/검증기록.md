# 양손 검 공격 모션 통일 · 2026-09-13

방패를 수납하고 검을 양손으로 잡은 상태에서도 검·방패와 동일한 기본 베기, 역방향 베기, 내려베기를 순환한다. 검의 기존 낮은 기본 위치를 유지했다.

## 확인된 원인과 수정

기존에는 방패 장착 여부로 공격 종류와 재생 시계를 함께 선택했다. 방패를 수납하면 양손으로 파지해도 기본 베기만 허용하고, 활성 구간이 0.30초에서 0.16초로 바뀌었다. 공격 모션의 공유 여부를 실제 방패 방어 여부에서 분리했다. 양손 파지와 검·방패 상태는 같은 궤적과 속도, 타격 시점 0.145초, 활성 구간 0.30초를 사용한다. 피해량과 기력 비용, 방패 수납 시 방어 해제는 유지했다.

수정 전 파일은 `baseline/`에 보존했다. 주요 변경은 `godot-game/scripts/player.gd`이며, 테스트룸 안내/카탈로그, README, TEST_ROOM, GAME_DIRECTION 및 관련 자동 검사와 렌더링 하네스를 함께 갱신했다. 원본 Blender 에셋과 이전에 수정한 복귀 모션 데이터는 변경하지 않았다.

## 실행 결과

- `unified_sword_motion`: 실제 플레이어 두 상태의 세 공격을 프레임별 비교. 위치 최대 차이 0m, 회전 최대 오차 약 0.056도(부동소수점 측정 오차 범위). 전투 단계와 차지 값도 매 프레임 일치했다.
- `sword_recovery_continuity`: 두 상태 × 세 공격의 복귀 검사 통과. 마지막 복귀 경계 위치 변화 0.33mm 미만. 불필요한 한 바퀴 회전 재발 없음.
- `primary_shield_stow`, `shield_guard`, `sword_attack_variants`: 통과.
- `reference_sword_motion_test_room`: 수납 후 실제 역방향 공격과 공유 타격 시계, F2 취소, 반복 실행, 초기화와 원정 복원 통과.
- 총 6종 검사 통과(테스트룸 보강 전후 포함 7회 실행). 상세 로그: `tests.log`, `regression.log`.
- 실제 Apple M4 Vulkan Forward+ 렌더링: 방패 수납, 달리기, 점프, 세 공격 총 6개 시퀀스 526프레임 저장. 렌더링 검사 실패 0. 양손 파지 완료 후 세 공격에서 왼손 손잡이 기준점 오차 최대 약 0.00000006m. 원정·커서·캡처 중 소스 보존 검사 통과.
- 세 공격의 공격/복귀 프레임을 직접 열어 확인했다. 실제 프레임으로 60fps 273프레임 MP4를 만들고 디코딩 프레임 수까지 검증했다. 별도 게임 창이나 OS 입력을 사용하지 않았으며 검증 프로세스는 종료됐다.

## 확인 범위와 산출물

렌더링은 기존 게임의 실제 플레이어 코드를 사용하는 검수 장면이다. 사용자가 실행 중인 게임을 재시작하거나 포커스를 빼앗지 않았다. 현재 실행 중인 게임 프로세스의 변경 반영은 미확인이다. 새 실행에 반영된다. 모델 표면 디테일은 이번 수정 범위가 아니다.

실제 렌더링 및 영상:
`godot-game/artifacts/visual_qa/reference_sword_motion/unified_two_hand_sword/`

- `unified_two_hand_attacks.mp4`: 세 공격 연속 확인
- `attack_review.jpg`: 공격·복귀 프레임 검수
- `capture_manifest.json`: 실제 렌더러, 전 프레임 자세와 검증 결과

로그에는 변수 이름 중복 등의 GDScript 경고와 일부 테스트 종료 시 ObjectDB 잔존 2개 경고가 남는다. 검사 실패나 스크립트 오류는 없었다.

직접 확인: F2 → 기본 → 주무장 1번 · 방패 수납 → 1 → LMB 반복.
