# Godot 작업

이 디렉터리는 Godot 4.7 프로젝트입니다. 상위 [프로젝트 지침](../AGENTS.md)을 따릅니다. 실행·검증 명령은 [README.md](README.md), 테스트룸 사용·확장은 [TEST_ROOM.md](TEST_ROOM.md)의 변경 관련 부분을 확인합니다.

# 필수 완료 조건: 모든 기능을 테스트룸에 함께 추가

신규 게임 기능과 기존 기능의 동작 확장은 **같은 변경에서** 다음을 모두 완료합니다. 테스트룸 반영을 후속 작업으로 미루지 않습니다.

1. `scripts/test_room_catalog.gd`에 실행 가능한 항목을 등록·확장합니다. 고유 `id`, 올바른 분류, 실제 동작과 일치하는 설명, `action`과 필요한 `payload`를 제공합니다.
2. `scripts/test_room.gd`의 `run_feature()`에서 실제 플레이 코드·UI·장면으로 연결합니다. 대상·초기 상태·이동 위치·회복·재생성 수단을 준비합니다. 이름·설명만 추가하거나 게임과 별개로 결과를 흉내 내는 항목은 완료가 아닙니다.
3. `tests/`의 자동 검증을 추가·확장하고 실행하여 등록, 실제 효과, 관련 회귀, 시험 상태 격리·복원을 확인합니다. 조작·실행 방법이 바뀌면 `TEST_ROOM.md`와 `README.md`도 갱신합니다.

## 카탈로그 자동 등록

- 물품: `ExpeditionInventory.ITEM_DEFINITIONS` → 물품 탭·시험 보급 상자.
- 마법: `SpellCatalog.ordered_spell_ids()` → 마법 탭·시험용 습득 목록.
- 상태이상: `ExpeditionSession.CONDITION_DRAIN_BONUSES` → 생존 탭.

위 유형은 원본 카탈로그를 확장하고 자동 등록 결과를 검증하며, 테스트룸에 중복 하드코딩하지 않습니다. 새 효과·시전 유형도 범용 시험 동작으로 실제 사용 가능한지 확인하고 필요한 실행 경로·검증을 추가합니다. 다른 신규 시스템은 명시적 카탈로그 항목·실행 동작을 추가하며, 미구현 효과를 지원한다고 표시하지 않습니다.

## 시험 세션 격리·복원

- 테스트룸과 연결 시험 장면은 `TestRoomSandbox` 소유의 별도 원정을 사용합니다. 입장 시 `ExpeditionSession.capture_snapshot()`으로 기존 상태를 보존한 뒤 `begin_new_journey()`로 시험 인벤토리를 분리합니다. 원본 인벤토리를 시험용으로 직접 변경하지 않습니다.
- 메인 메뉴 복귀 시 보존 상태를 복원합니다. 원본 인벤토리 참조·연결 신호를 유지하고 나머지 변경 가능한 Dictionary는 깊은 복사합니다.
- `ExpeditionSession` 상태 필드 추가 시 `capture_snapshot()`, `restore_snapshot()`, `tests/test_room_session_test.gd`도 함께 확장합니다.
- 테스트룸 `F2` 메뉴, 연결 장면 `F2` 복귀, 초기화, 사망·생환 후 재시험을 유지합니다. 시험 메뉴가 열린 동안 전투·생존 시간은 정지해야 합니다.

# 검증 범위와 실행

- 변경 기능·관련 회귀·테스트룸 검증과 해당 문서의 필수 검증 목록을 실행합니다. 관련 검증이 통과하면 추가 변경·실패·미해결 위험 없이 같은 테스트나 전체 검증을 반복하지 않습니다. 문서만 바꿔 게임 동작에 영향이 없으면 내용·링크를 확인하고 Godot 실행은 생략합니다.
- 자동 검증은 Codex 내부 백그라운드 세션에서 [tests/run_headless_tests.sh](tests/run_headless_tests.sh)를 사용합니다. 인자로 시험 이름을 지정하면 해당 시험만, 인자가 없으면 모든 `tests/*_test.gd`를 독립된 `--headless` 프로세스로 순차 실행합니다. 실행 파일·기본값은 실행기를 따르며 macOS의 낮은 CPU·I/O 우선순위를 유지합니다.
- 편집기·프로젝트 매니저·게임·별도 Terminal 창을 띄우지 않습니다. 로그는 현재 Codex 작업 안에서 수집하고 통과·실패를 요약하며, 검증용 사이드바 작업은 만들지 않습니다. 완료 시 검증이 시작한 Godot 프로세스가 남지 않았는지 확인하고 사용자가 열어 둔 프로세스는 조작·종료하지 않습니다.

## UI·3D·입력을 바꾼 경우

헤드리스 자동 검증을 먼저 완료한 뒤 실제 화면·조작도 확인합니다. 이 macOS 빌드의 `--headless`는 더미 렌더러이므로 PNG 출력을 실제 화면 검증으로 간주하지 않습니다.

[숨김 렌더링 안내](tests/EMBEDDED_RENDERING.md)와 해당 `*_preview.gd`를 확인하여, 방해 없이 완전한 검증이 가능한 숨김·비활성 실행을 우선합니다. 실제 렌더 결과를 `artifacts/visual_qa/`에 저장해 직접 검토하며, 로컬 GUI 이벤트 검증으로 OS 포커스·하드웨어 입력까지 검증했다고 주장하지 않습니다.

`grab_focus()`, 마우스 캡처, `Input.warp_mouse()` 또는 인터랙티브 변수 등으로 포커스·커서·소리를 방해하는 실행은 사용자 작업 중에 자동 실행하지 않습니다. 숨김 방식으로 필요한 검증을 마칠 수 없다면 실행 전에 필요성과 예상 영향을 알리고 확인받습니다. `*_QA_INTERACTIVE=1`은 자동으로 사용하지 않습니다.
